# chatgpt2api Deployment

The chatgpt2api sidecar is retired and is not an active container on `.114`.
Its source patches and Compose snapshot are retained as historical evidence,
not instructions to rebuild, install, or restart it. Flaresolverr's continued
presence does not mean chatgpt2api is running.

## Retired launcher

This directory's `cliproxy-compose` refuses to start services. The active CPA
wrapper is maintained at `deploy/gemini-web-local/cliproxy-compose` and installed
at `/usr/local/sbin/cliproxy-compose`. It uses only the current
`docker-compose.dashboard-only.yml` (CPA and Postgres), without sidecar overlays
or sidecar credential preparation. Do not recreate these retired services.

Run the historical launcher checks without Docker or real secrets:

```bash
python3 -B -m unittest discover -s deploy/chatgpt2api/tests -p 'test_startup.py' -v
```

The tests trap external-secret CLI calls and fake Docker.

The following sections describe the retired image and preserve its patch evidence.

## English Locale

`0002-english-ui-and-locale.patch` applies after the existing local patch on vendor
revision `e55aef2`. It changes the dashboard's built-in labels, defaults, messages,
date formatting, HTML language and ordinary upstream language headers to English.
It also preserves timeout recognition for both new English messages and older
stored messages.

The patch includes `test_english_request_locale.py` and
`test_english_backend_messages.py`. Run those with the vendor's existing offline
unit tests, run `npx tsc --noEmit` separately from the frontend build, and build the
static frontend before packaging the image. The vendor's Next.js configuration
skips type checking during `next build`, so a successful build alone is not a
typecheck.

## Preserved Data

Account status codes, upstream parsing keywords and release-category identifiers
remain unchanged. The UI maps those codes to English labels rather than migrating
stored account data. User prompts, configured system prompts, existing conversation
titles, historical logs and upstream release-note content are not rewritten.

`OAI-Language: en-US` and an English `Accept-Language` express a language preference.
They do not guarantee the language of a title generated by an upstream service,
and they do not rename existing library items.

## Rollout

`0003-image-policy-errors-and-poll-diagnostics.patch` applies after `0002`.
It recognizes the upstream "may violate our guardrails" refusal, propagates
confirmed policy errors without further polling, and returns HTTP 400 with
`content_policy_violation` instead of waiting until a misleading HTTP 502 timeout.
Polling diagnostics contain allowlisted states, counts and a conversation UUID,
not prompts, tokens or upstream error text. Run the isolated backend checks with:

```bash
.venv/bin/python -B -m test.run_image_poll_offline
```

Keep `image_remove_conversation_always=false` and
`image_remove_conversation_after_result=true`: unsuccessful upstream conversations
remain available for diagnosis while successful conversations are cleaned up.
The current image wait budget is 300 seconds; it does not override upstream
policy refusals or rate limits. No frontend changes are included in this patch.

Keep the active `/run/cliproxy` configuration intact for image-only updates. Update
only the chatgpt2api service after validating the built image, without recreating
CPA, the database or other sidecars. A browser reload is needed to load the new
static frontend assets.
