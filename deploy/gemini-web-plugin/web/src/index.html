GWGemini Web

CLIProxyAPI 플러그인

Gemini Web 계정 관리 화면을 준비하고 있습니다.

요청 방법

이 플러그인이 발행하는 모델은 gemini-omni-1.1-flash 하나이고, 호출 경로는 공식 Interactions 표면 POST /v1beta/interactions입니다. 아래 예시의 $CLIPROXY는 이 프록시의 베이스 URL, $CLIPROXY_KEY는 발급받은 API 키입니다.

POST/v1beta/interactions호출당 영상 1건 소비

요청

curl -X POST "$CLIPROXY/v1beta/interactions" \
  -H "Authorization: Bearer $CLIPROXY_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-omni-1.1-flash",
    "input": "노을 지는 해변을 걷는 사람",
    "response_format": { "type": "video", "aspect_ratio": "16:9" },
    "store": true
  }'

필드

필드타입허용값설명
inputstring 또는 배열텍스트 한 건, 또는 text·image·video 파트 배열첨부는 data+mime_type으로 인라인이거나, uri로 Drive 파일을 가리킵니다. 영상 첨부는 참조 선언이 자동으로 붙습니다.
response_format.typestringvideo생략하면 영상입니다. 그 밖의 값은 거부합니다.
response_format.aspect_ratiostring16:9 · 9:16웹 UI와 같은 프레이밍 칩과 방향이 함께 전송됩니다. 생략하면 16:9. 실측(2026-09-15): 16:9는 1280x720이 나오지만 9:16은 업스트림이 영상을 만들지 않아 실패합니다.
previous_interaction_idstring완료·저장된 interaction id그 영상을 이번 턴의 참조 첨부로 싣습니다. 계정에 묶이지 않습니다 — 다른 계정이 이어받아 생성할 수 있습니다(실측 2026-09-17).
storeboolean기본 truefalse면 완료 후 영수증을 폐기하므로 이후 조회·체이닝이 불가합니다.

stream·background·response_format.resolution·response_format.delivery: "uri"는 전송 슬롯도 대응물도 없어 생성 전에 거부합니다.

응답

{
  "id": "efa78dd45816fdd2…",
  "object": "interaction",
  "model": "gemini-omni-1.1-flash",
  "account": "gemini-web-….json",
  "status": "completed",
  "error": null,
  "steps": [{
    "type": "model_output",
    "content": [{ "type": "video", "mime_type": "video/mp4", "data": "AAAAIGZ0eXB…" }]
  }]
}

업스트림 다운로드 URL이 세션 쿠키로만 열리기 때문에 링크 대신 base64 본문으로 돌려줍니다. 실측 소요는 60~100초, 결과물은 1.8~6.5MB입니다.

제약

  • 새 프롬프트는 한 턴. 대화 이력을 직접 싣거나 업스트림 식별자를 건네줄 수 없습니다.
  • 프롬프트는 8000자 이하.
  • 영상이 준비될 때까지 최대 10분 폴링합니다. 제출 자체가 오래 걸리면 그만큼 더 기다릴 수 있습니다.
  • 생성 사이에 쿨다운이 있습니다. 직전 영상 직후 다시 호출하면 no_video_generated로 거절되니 간격을 두세요.
  • POST 재시도는 복구가 아니라 새 생성입니다. 응답을 놓쳤으면 아래 GET으로 조회하세요.
GET/v1beta/interactions/{id}조회 · 쿼타 소모 없음

요청

curl "$CLIPROXY/v1beta/interactions/$INTERACTION_ID" \
  -H "Authorization: Bearer $CLIPROXY_KEY"

완료된 영수증은 저장된 결과를 그대로 재생하므로 재생성하지 않습니다. 진행 중이면 status: "in_progress"로 답하고, 같은 id로 다시 물어보면 됩니다. 영수증은 계정과 호출자에 묶여 있어 다른 API 키로는 조회되지 않습니다.

4xx/5xx오류 코드 · 생성 이후쿼타가 이미 소모됨
코드의미
gemini_web_omni:no_video_generated업스트림이 답은 했지만 영상을 만들지 않았습니다. 쿨다운이 흔한 원인이니 간격을 두고 다시 호출하세요.
missing_upstream_operation제출 스트림이 작업 이름을 남기지 못했습니다. 계정은 자동으로 회수되며, 재시도는 새 생성입니다.
web_response_failed제출 응답이 도중에 끊겼습니다. 이름이 남았다면 같은 id로 GET 조회하세요.
invalid_video_download영상은 준비됐는데 내려받기가 실패했습니다. 같은 id로 다시 조회하세요.
gemini_web_omni:auth_error계정 로그인이 만료됐습니다. 계정 화면에서 다시 연결하세요. 이 경우 제출 전에 멈추므로 쿼타는 쓰지 않습니다.

실패해도 HTTP 상태는 200으로 도착할 수 있습니다. 성공·실패는 상태코드가 아니라 본문의 status와 error로 판단하세요.
